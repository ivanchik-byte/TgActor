# TgActor workspace

## Направление

Сдержанный премиальный рабочий интерфейс. Постоянная графитовая навигация с шалфейным активным пунктом служит визуальным ориентиром. Светлая рабочая область, изумрудные действия и общая полоса показателей отделяют управление от данных.

Оценка направления по DFII: 13/15 (выразительность 4, соответствие продукту 5, реализуемость 5, производительность 4, риск рассогласования 5).

## Дизайн-система

- Manrope: интерфейс и заголовки, включая кириллицу.
- IBM Plex Mono: служебные подписи, идентификаторы и технические значения.
- Поверхности светлой темы: `#f5f6f3`, `#ffffff`, `#eef1ec`.
- Основной текст: `#202c28`; вторичный: `#64716a`.
- Акцент: `#24785c`; навигация: `#18221e`; активный пункт: `#c3d5ad`.
- Статусы используют общие переменные success, warning и danger.
- Геометрия: шаг 4/8 px, рабочие интервалы 20–38 px, радиусы панелей 13–18 px и контролов 8 px.
- Phosphor Icons заменяют прежний набор иконок во всём интерфейсе.
- Выпадающие списки используют Radix Select: собственные поверхности, выделение, клавиатурную навигацию, группы вариантов и отображение поверх модальных окон. Существующие обработчики изменения получают событие настоящего скрытого select.
- Системные confirm-окна заменены диалогом приложения. Тексты рассчитаны на личный open-source инструмент без ролей владельца, администратора или тарифов.
- Анимация ограничена появлением разделов, загрузкой и откликом элементов. `prefers-reduced-motion` отключает её.

Сохранены идентификаторы всех четырёх тем и выбор пользователя. Новые пользователи получают светлую тему. Тёмные варианты: «Графит», «Сланец», «Бордо».

## Разделы

Переработаны оболочка, вход, аккаунты, пулы, каналы, сценарии, промпты, входящие и история. Все маршруты и API операций сохранены. На ноутбуке параметры сценария и симуляция располагаются под широким редактором; на большом экране используется три колонки. На телефоне навигация открывается в панели, а рабочие области располагаются последовательно.

Проверки интерфейса используют только тестовые HTTP-ответы и WebSocket. Они не запускают реальные Telegram-операции.

## Локальная работа

Запускать из каталога `frontend`:

```sh
npm install
npx playwright install chromium
npm run dev
npm run build
npm run lint
npm test
```

Vite передаёт `/api`, `/media` и `/ws` на локальный backend `127.0.0.1:8000`. Для раздельного размещения сохранена настройка `VITE_API_URL`. Production-сборка находится в `frontend/dist` и обслуживается существующим backend.

## Проверка

34 браузерные проверки в Chromium: 17 сценариев на компьютере и телефоне. Покрыты семь разделов с данными, вход и ошибка пароля, поиск и фильтрация аккаунтов, запрос кода Telegram, сохранение темы, навигация, сохранение шагов сценария, отправка сообщения из инбокса, пустой список и ошибка сервера. Отдельно проверяются фон навигации на всю высоту длинной страницы, доступность меню при прокрутке и высота мобильной панели. Проверяется отсутствие горизонтального выхода содержимого за границы экрана, включая ширины 360, 375, 768 и 1024 px. Удаление шаблона проверяется с отменой и подтверждением.

Скриншоты можно получить командой `CAPTURE_UI=1 npm test`; они сохраняются в игнорируемом каталоге `frontend/test-results`. Эти проверки подтверждают поведение фронтенда и контракт запросов, а не работу реального Telegram или внешнего ИИ.
